Publicar tu sitio sin usar la terminal

Todo desde el navegador · unos 25 minutos

Buena decisión. Este camino te ahorra instalar Git, generar la llave ghp_ y usar la ventana negra. Solo necesitas arrastrar archivos en una página web.

Esta guía cubre por completo el paso 2 del archivo EMPIEZA-AQUI.md.

Los dibujos de esta guía son esquemas, no fotos. Muestran dónde está cada cosa. Si GitHub movió algún botón, busca el mismo texto en pantalla.

Parte 1Crear tu cuenta

  1. Entra a github.com
  2. Botón Sign up, arriba a la derecha
  3. Correo, contraseña y nombre de usuario
  4. Te llega un código al correo. Cópialo y pégalo.
Elige bien el nombre de usuario. Aparece en direcciones públicas. Algo como imermoreno. No un apodo.

Parte 2Crear el espacio para tu sitio

En github.com, arriba a la derecha junto a tu foto, hay un signo +. Clic ahí → New repository.

Nombre sitio-lma, deja Public, y no marques ninguna de las tres casillas.
Si marcas alguna casilla el siguiente paso se complica. Déjalas vacías.

Parte 3Subir tus archivos arrastrando

Después de crear el repositorio, GitHub te muestra una página con instrucciones. Ignora casi todo. Busca el enlace que dice:

uploading an existing file

Ese enlace pequeño es el que te lleva a la subida por arrastre.

Prepara la selección

Abre el Explorador de Windows y entra a la carpeta C:\proyectos\sitio-lma.

Presiona Ctrl + E para seleccionar todo lo que hay adentro.

Este es el error que más se comete. Tienes que arrastrar lo que está dentro de la carpeta, no la carpeta misma.

Si arrastras la carpeta sitio-lma completa, tu sitio quedará en tudominio.com/sitio-lma/index.html en lugar de tudominio.com, y Cloudflare no lo encontrará.
sitio-lma/index.html y el sitio no cargaría Atajo: entra a la carpeta y presiona Ctrl + E para seleccionar todo el contenido.
Izquierda: bien. Derecha: mal.

Arrastra

Con todo seleccionado, arrástralo desde el Explorador hasta el recuadro punteado de la página de GitHub.

Suelta los archivos en el recuadro punteado, escribe una nota y confirma.
  1. Suelta los archivos en el recuadro punteado
  2. Espera. Verás la lista subiendo. Con tus ~27 archivos tarda menos de un minuto.
  3. Abajo, donde dice Commit changes, escribe Sitio inicial
  4. Botón verde Commit changes
Comprobación. La página se recarga y debes ver la lista de tus carpetas: admin-cms, data, herramientas, img, js, y abajo tus archivos .html.

Que index.html se vea en esta lista principal es la señal de que lo hiciste bien. Si en cambio ves una sola carpeta llamada sitio-lma, arrastraste la carpeta en vez del contenido: bórrala y repite.

Si arrastrar no funciona

Algunos navegadores no permiten arrastrar carpetas. Usa el enlace choose your files, pero ojo: ese selector solo toma archivos sueltos, no carpetas. En ese caso sube primero los .html, y luego repite la operación entrando a cada carpeta del repositorio con Add file → Upload files.

Más fácil: usa Chrome o Edge, donde el arrastre de carpetas sí funciona.

Parte 4Publicarlo en internet

  1. Entra a dash.cloudflare.com → Sign up. No pide tarjeta.
  2. Menú de la izquierda: Workers & Pages
  3. Botón Create → pestaña Pages → Connect to Git
  4. Connect GitHub → te manda a GitHub → elige Only select repositories → marca sitio-lma → Install & Authorize
  5. De regreso en Cloudflare, selecciona sitio-lma → Begin setup

La configuración

Aquí es donde más gente se equivoca. Llénala exactamente así:

Framework preset en None, build command vacío, y output directory con una diagonal.

Espera dos minutos. Verás texto corriendo. Al final dirá Success y te dará tu dirección:

https://sitio-lma.pages.dev

Tu sitio ya está en internet. Ábrelo desde el celular para ver que se vea bien ahí también.

Parte 5Cómo actualizarlo de ahora en adelante

Todo desde github.com. Nunca vuelves a entrar a Cloudflare: él solo detecta los cambios y republica en un minuto.

Cambiar un archivo

  1. Entra a tu repositorio, navega hasta el archivo
  2. Clic en el icono del lápiz, arriba a la derecha del recuadro
  3. Edita
  4. Abajo: Commit changes → Commit changes

Subir archivos nuevos

  1. Entra a la carpeta donde van (por ejemplo img → portafolio)
  2. Add file → Upload files
  3. Arrastra y confirma

Agregar un proyecto al portafolio

Es el mismo procedimiento, en dos partes:

QuéDónde
La fotoCarpeta img/portafolio/ → Add file → Upload files
Los datosArchivo data/proyectos.json → lápiz → editar
El panel de administración encaja perfecto con este camino. Ábrelo en sitio-lma.pages.dev/admin.html, agrega tus proyectos con el formulario, y al terminar descarga el proyectos.json desde "Admin / System Ops". Ese archivo lo subes a la carpeta data reemplazando el anterior, y las fotos que se descargaron solas las subes a img/portafolio. Sin terminal en ningún momento.

PendienteLas fotos prestadas

Recuerda que las fotos de tu sitio todavía son enlaces a servidores de Google, donde Stitch las dejó. Funcionan hoy, pero pueden desaparecer.

El script que las rescata (herramientas\descargar-imagenes.py) sí necesita la terminal. No es urgente hacerlo ahora. Publica primero.

Cuando quieras resolverlo sin terminal, hay una forma manual: abrir tu sitio, hacer clic derecho sobre cada imagen → Guardar imagen como, subirlas a img/portafolio desde github.com, y corregir las rutas en data/proyectos.json. Son unas trece imágenes.

Si algo fallaLos tres problemas típicos

Cloudflare dice Success pero el sitio sale en blanco o da 404

Dos causas posibles:

  • El Build output directory no es /. Corrígelo en Settings → Builds & deployments → Configure Production deployments, guarda y dale Retry deployment.
  • Subiste la carpeta en vez del contenido. Entra a tu repositorio: si ves una sola carpeta sitio-lma en la lista principal, ese es el problema. Bórrala y vuelve a subir el contenido.

La galería del portafolio sale vacía en el sitio publicado

El archivo data/proyectos.json no subió, o tiene un error de sintaxis. Ábrelo en github.com y comprueba que se vea el contenido. Si lo editaste, valídalo en jsonlint.com antes de guardar.

Subí un archivo mal y quiero borrarlo

Entra al archivo en github.com, clic en los tres puntos arriba a la derecha → Delete file → Commit changes.

Si te atoras. Anota en qué parte te quedaste y qué dice exactamente el mensaje en pantalla. Con eso se resuelve rápido.
