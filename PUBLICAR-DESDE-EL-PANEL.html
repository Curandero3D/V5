Publicar directo desde el panel

Agregar un proyecto y que aparezca en tu sitio, sin pasar por GitHub · 15 minutos de configuración, una sola vez

Qué vas a lograr

Ahora mismo, para publicar un proyecto tienes que: llenar el formulario, descargar el archivo, entrar a github.com, subirlo. Cuatro pasos.

Al terminar esta guía será: llenar el formulario y dar Guardar. El panel sube la foto y actualiza el portafolio solo. Tu sitio se refresca en un minuto.

Para que el panel pueda escribir en tu repositorio necesita un permiso: un token. Es como una llave de repuesto que solo abre una puerta.

Parte 1Crear el token

Entra a github.com y sigue este camino. El último tramo está muy escondido:

Elige Fine-grained: ese tipo se limita a un solo repositorio, así que es mucho más seguro.

Ya ahí, botón Generate new token. Llena así:

Lo esencial: solo el repositorio sitio-lma, y en permisos solo Contents: Read and write.
Por qué solo ese permiso. Ese token únicamente puede leer y escribir archivos en ese repositorio. No puede borrar el repositorio, ni tocar otros, ni entrar a tu cuenta. Si algún día se filtra, el daño posible es mínimo y lo cancelas en dos clics.

Botón Generate token hasta abajo.

El token se muestra UNA SOLA VEZ. Es una cadena larga que empieza con github_pat_. Cópiala ahora mismo y guárdala en el Bloc de notas. Si cierras la página sin copiarla, hay que generar otra.

Parte 2Configurar el panel

  1. Abre tu sitio y haz clic en el candado del pie de página
  2. Escribe la contraseña
  3. Ya en el panel, abajo a la izquierda dice Admin / System Ops. Haz clic ahí.
Escribe el repositorio, pega el token, y prueba antes de guardar.

Cómo escribir el repositorio

Va en formato usuario/repositorio, con diagonal en medio. Si tu usuario es imermoreno, sería:

imermoreno/sitio-lma

CorrectoIncorrecto
imermoreno/sitio-lma https://github.com/imermoreno/sitio-lma
sitio-lma
imermoreno / sitio-lma (con espacios)

Prueba antes de guardar

El botón PROBAR CONEXIÓN verifica que todo esté bien y te dice exactamente qué falla si algo falla:

MensajeSignifica
Conexión correctaListo, dale Guardar
Token inválido o vencidoCopiaste mal el token, o ya caducó
No tiene permiso de escrituraFaltó poner Contents: Read and write
No se encontró el repositorioEscribiste mal el nombre, o el token no incluye ese repositorio

Cuando diga que la conexión es correcta, botón GUARDAR.

Parte 3Publicar un proyecto

  1. Botón + NUEVO PROYECTO
  2. Clic en el recuadro punteado y elige la foto directo del celular o la cámara, sin comprimirla
  3. Llena título, categoría, estado y descripción
  4. Botón GUARDAR DATOS

Verás mensajes en la esquina: "Subiendo la imagen…", "Actualizando el portafolio…", y al final "Publicado. Tu sitio se actualiza en aproximadamente un minuto."

Espera ese minuto, abre tu sitio y ahí está.

Ya no necesitas comprimir las fotos. El panel lo hace solo: reduce a 1600 píxeles de ancho y las convierte a WebP. Una foto de 5 MB queda en unos 250 KB, sin diferencia visible. El mensaje te dice cuánto pesaba y cuánto quedó. Olvídate de Squoosh.

Editar o borrar

Cada tarjeta tiene un lápiz y un bote de basura. Ambos publican automáticamente igual que el guardado.

Si cambias la foto de un proyecto que ya existía, el panel reemplaza la anterior en el repositorio. No se acumulan copias.

ImportanteDónde queda el token

Se guarda solo en el navegador de la computadora donde lo escribiste. No viaja a ningún servidor mío ni de nadie: únicamente a GitHub, cuando publicas.

SituaciónQué hacer
Tu computadora personalActívalo sin problema
Computadora compartida o prestadaNo lo actives. Usa el modo borrador
Vas a prestar tu computadoraEntra al panel → Admin / System Ops → OLVIDAR TOKEN
Crees que se filtróEn GitHub: Settings → Developer settings → Fine-grained tokens → Revoke. Genera otro.

Si borras el historial del navegador, el token se borra también y hay que volver a escribirlo. Por eso conviene tenerlo guardado en el Bloc de notas.

Si algo fallaQué significa cada mensaje

Mensaje del panelSolución
El token no es válido o ya venció Genera uno nuevo (Parte 1) y actualízalo en la configuración
El token no tiene permiso de escritura Al crearlo faltó Contents: Read and write. Genera otro con ese permiso.
No se encontró el repositorio Revisa el formato usuario/repositorio. Sin https://, sin espacios.
Conflicto al guardar Editaste el JSON en github.com al mismo tiempo. Recarga el panel y repite.
No hubo respuesta de GitHub Revisa tu conexión a internet.
Tus cambios nunca se pierden. Si la publicación falla, el proyecto sigue en el panel. Puedes reintentar, o usar DESCARGAR proyectos.json y subirlo a mano como respaldo.
